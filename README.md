# Terminal_Q — хаб офіційних сторінок розробника

Цей репозиторій — **хаб юридичних/публічних сторінок розробника**
(Privacy Policy, Terms of Service, Security, Support, About), на які зможе
посилатись будь-який ІТ-проєкт, що публікується під брендом **Terminal_Q**.

**`ai-bridge-site` — не тестовий приклад, а основний продукт**, заради якого
цей хаб і робиться: він уже готовий до публікації й монетизації, і саме йому
потрібні всі ці юридичні сторінки, а не хаб йому як "заглушка". Локально в
`../ai-bridge-site`, зараз задеплоєний на
`https://ai-bridge-beta.legotron.chatgpt.site` — назва "Artifacto Bridge"
**вилучена**, "Bridge" також визнано занадто загальною назвою продукту. Нова
назва ще не вибрана; продукт потребує доробки й перейменування (окрема
робота, не в цьому репозиторії).

> Посилання на `ai-bridge-site` нижче — відносні (`../ai-bridge-site`) і
> працюють лише локально, поки обидва проєкти лежать поряд на диску. Коли
> буде відомий GitHub owner/repo цього хабу й `ai-bridge-site`, замінити на
> абсолютні canonical URL (репозиторію та/або задеплоєного сайту).

**Поточний фокус цього репозиторію — виключно бюрократично-організаційні
речі**: юридичні сторінки, бренд розробника, GitHub-профіль. Сам продуктовий
код (`ai-bridge-site`, VS Code розширення — див. "Продукти портфоліо" нижче)
в рамках цього репозиторію не чіпається.

Документ фіксує рішення, прийняті в розмові, і план подальших кроків, щоб
наступна сесія (людина чи інша модель) могла продовжити без перепитувань.

### Політика мінімального розкриття персональних даних

За замовчуванням на публічних сторінках **не** публікуються: повне ім'я по
батькові, домашня/юридична адреса, телефон, дата народження, номер
паспорта/ІПН чи інші державні ідентифікатори. Дозволено: прізвище + ініціали,
контактний email (`terminalq.dev@gmail.com`), назва бренду.

Виняток — якщо конкретна платформа публікації (Stripe, App Store, ChatGPT
Apps, банк-еквайр тощо) технічно вимагає повних реквізитів для верифікації —
тоді розширений набір даних надається саме туди (у формі платформи), а не
виставляється на публічній сторінці хабу.

моделі потрібно окремо визначити, хто юридично є замовником і платником —

**Дія перед запуском платежів:** перевірити цю модель з бухгалтером/податковим
консультантом; за потреби розглянути 3 групу. Terms/Privacy тексти в цьому
хабі написані **нейтрально**, без прив'язки до конкретної групи ФОП, щоб не
потребувати переписування після цього рішення. Це не юридична консультація.

## Сторінки хабу (план)

Мінімальний "повний фарш" для публікації й монетизації будь-якого проєкту.
Шляхи нижче (`/privacy`, `/terms`, ...) — умовні, кінцевого вигляду набудуть
залежно від deployment-моделі:

- **Обрано: user-site** `terminal-q.github.io` → шляхи такі, як записано (`/privacy`, `/terms`, ...), без префіксу.
- Це вимагає, щоб репозиторій на GitHub називався **точно** `terminal-q.github.io` — інакше GitHub Pages піде в project-site режим із префіксом `/offsite/...`.
- До моменту фактичного push на GitHub локальна папка лишається `D:\Kod\offsite` — назва локальної теки не впливає на URL, важлива тільки назва remote-репозиторію.

- `/` — головна / про розробника (аналог наявного `app/developer/page.tsx` в `ai-bridge-site`, але як канонічне джерело)
- `/privacy` — Privacy Policy (яких даних торкається, як зберігаються/видаляються, GDPR-подібні права)
- `/terms` — Terms of Service (умови використання, відповідальність, обмеження гарантій)
- `/security` — Security Policy / Responsible Disclosure (як повідомити про вразливість, SLA на відповідь)
- `/support` — Support / Contact (email, очікуваний час відповіді, канали)
- `/refunds` — Refund / Cancellation Policy (додається разом із першою платною підпискою)
- `/cookies` — Cookie Policy (додається, якщо на сайтах з'являється аналітика/трекінг)

Кожна сторінка — двомовна (uk/en), за зразком i18n-патерну з
`ai-bridge-site` (`components/public/i18n.ts`, `COPY` record).
